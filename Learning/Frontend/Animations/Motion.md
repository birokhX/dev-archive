`resources/js/animations/ui/card-entry.js`
```js
import { animate } from "motion";
export function animateCardEntry() {
    const card = document.querySelector(
        '[data-motion="card-entry"]'
    );

    if (!card) {
        return;
    }

    animate(
        card,
        {
            opacity: [0, 1],
            y: [24, 0],
        },
        {
            duration: 0.65,
            ease: "easeOut",
        }
    );
}
```
#### توضیح این بخش

تابع `animate` سه ورودی اصلی این مثال را دریافت می‌کند:

| ورودی   | مسئولیت                            |
| ------- | ---------------------------------- |
| `card`  | عنصری که باید انیمیت شود           |
| شیء دوم | ویژگی‌های انیمیشن و مقدارهای آن‌ها |
| شیء سوم | تنظیمات زمان‌بندی و رفتار حرکت     |

## معنی ویژگی‌های انیمیشن

#### `opacity: [0, 1]`

تأثیر: شفافیت کارت از صفر به یک می‌رسد؛ صفر یعنی کاملاً شفاف و یک یعنی کاملاً غیرشفاف.
تغییر آزمایشی: مقدار اولیه را به `0.2` تغییر بده تا کارت از ابتدا کمی قابل مشاهده باشد.

#### `y: [24, 0]`

تأثیر: کارت از موقعیتی ۲۴ پیکسل پایین‌تر از جای نهایی وارد می‌شود و به مختصات عمودی صفر می‌رسد.
تغییر آزمایشی: مقدار `24` را به `80` تغییر بده. حرکت شروع کارت محسوس‌تر خواهد شد.

#### `duration: 0.65`

تأثیر: مدت انیمیشن، برحسب ثانیه، ۰٫۶۵ ثانیه است.
تغییر آزمایشی: آن را به `1.5` تغییر بده و تفاوت سرعت را ببین.

#### `ease: "easeOut"`

تأثیر: سرعت در ابتدای حرکت بیشتر است و در انتها کاهش پیدا می‌کند؛ این رفتار باعث می‌شود کارت هنگام رسیدن به جایگاه نهایی نرم‌تر متوقف شود.
تغییر آزمایشی: مقدار را به `"linear"` تغییر بده تا حرکت سرعت یکنواخت‌تری داشته باشد.


نکته‌ای که باید از همین ابتدا درک کنی: آرایه‌هایی مانند `[24, 0]` و `[0, 1]` مقدارهای ابتدا و انتهای انیمیشن را مشخص می‌کنند. این‌ها دو مقدار هدف مستقل نیستند؛ یک مسیر تغییر را تعریف می‌کنند. Motion مقادیر بین این نقاط را در طول انیمیشن محاسبه می‌کند.

## جلسه دوم Motion: انیمیشن ورود و خروج عناصر
در جلسه قبل، یاد گرفتی چطور یک عنصر HTML را با `animate()` متحرک کنی. حالا باید سراغ یکی از مهم‌ترین مفاهیم Motion در پروژه‌های واقعی برویم: تفاوت انیمیت‌کردن یک عنصر با مدیریت چرخه ورود و خروج آن از صفحه.

مثلاً در Smarticard فرض کن فهرستی از کارت‌ها داری و کاربر می‌تواند یک کارت را حذف کند. اگر بلافاصله عنصر را از DOM حذف کنیم، انیمیشن خروج فرصت اجراشدن ندارد. باید ترتیب عملیات را درست طراحی کنیم.

در این جلسه روی سه مهارت تمرکز می‌کنیم:

- نمایش تدریجی چند کارت با تأخیر کنترل‌شده.
    
- حذف کارت همراه با انیمیشن خروج.
    
- درک تفاوت بین وضعیت رابط کاربری و حضور واقعی عنصر در DOM.
    

## مرحله اول: نمایش چند کارت با `stagger()`

در داشبوردی که چند کارت آماری دارد، اگر تمام کارت‌ها دقیقاً هم‌زمان ظاهر شوند، نتیجه ممکن است خشک و ناگهانی به نظر برسد. با قابلیت `stagger()` شروع انیمیشن هر کارت را کمی عقب می‌اندازیم. این قابلیت در مستندات رسمی Motion برای فهرست‌ها، شبکه کارت‌ها و منوها معرفی شده است

```html
<section class="grid gap-4 sm:grid-cols-3">
    <article data-motion="stat-card"
             class="rounded-2xl bg-slate-900 p-6 text-white">
        <p class="text-sm text-slate-400">تعداد کاربران</p>
        <p class="mt-3 text-3xl font-bold">1,240</p>
    </article>

    <article data-motion="stat-card"
             class="rounded-2xl bg-slate-900 p-6 text-white">
        <p class="text-sm text-slate-400">تعداد قالب‌ها</p>
        <p class="mt-3 text-3xl font-bold">36</p>
    </article>

    <article data-motion="stat-card"
             class="rounded-2xl bg-slate-900 p-6 text-white">
        <p class="text-sm text-slate-400">کسب‌وکارها</p>
        <p class="mt-3 text-3xl font-bold">520</p>
    </article>
</section>
```
### ۲. کد Motion

در فایل `resources/js/animations/ui/card-entry.js` تابع قبلی را با نسخه زیر جایگزین کن:
```js
import { animate, stagger } from "motion";

export function animateCardEntry() {
    const cards = document.querySelectorAll(
        '[data-motion="stat-card"]'
    );

    if (!cards.length) {
        return;
    }

    animate(
        cards,
        {
            opacity: [0, 1],
            y: [24, 0],
        },
        {
            duration: 0.5,
            ease: "easeOut",
            delay: stagger(0.12),
        }
    );
}
```
در اینجا `querySelectorAll()` تمام کارت‌ها را انتخاب می‌کند و `stagger(0.12)` باعث می‌شود شروع انیمیشن هر کارت نسبت به کارت قبلی ۰٫۱۲ ثانیه فاصله داشته باشد.

ویژگی‌های مهم این مثال:

- `stagger(0.12)`: فاصله زمانی بین شروع انیمیشن کارت‌ها.
    
- `duration: 0.5`: مدت حرکت هر کارت، نیم ثانیه.
    
- `opacity` و `y`: به‌ترتیب تغییر شفافیت و موقعیت عمودی.


### مثال دوم: چند مرحله در یک انیمیشن

```js
animate(card, {
    y: [0, -12, 0],
});
```
اینجا عنصر ابتدا بالا می‌رود و سپس به جای اولیه بازمی‌گردد.

می‌توانی همین مفهوم را برای چرخش، شفافیت و رنگ نیز به‌کار ببری؛ البته نوع مقادیر باید برای ویژگی موردنظر قابل انیمیت باشد.

## زمان‌بندی و Easing را درست یاد بگیر

دو انیمیشن ممکن است هر دو ۳۰۰ میلی‌ثانیه طول بکشند، اما حس کاملاً متفاوتی داشته باشند. علت یکی از تفاوت‌های مهم، `ease` است.
`linear`

سرعت در طول انیمیشن ثابت می‌ماند. برای حرکت‌های یکنواخت و برخی جلوه‌های تکرارشونده مفید است.

`easeOut`

حرکت سریع‌تر شروع می‌شود و در انتها آرام می‌شود. برای ورود کارت و پاسخ سریع رابط کاربری انتخاب مناسبی است.

`easeInOut`

حرکت آرام شروع می‌شود، در میانه سرعت می‌گیرد و در پایان آرام می‌شود. برای حرکت‌هایی که از یک وضعیت به وضعیت دیگر می‌روند مناسب است.

این گزینه‌ها در Motion به‌عنوان منحنی‌های Easing در دسترس هستند
## ۵. تفاوت `tween` و `spring`

این یکی از مفاهیم مهم Motion است.

#### `tween`: حرکت با زمان‌بندی مشخص
```js
animate(
    card,
    { y: -8 },
    {
        type: "tween",
        duration: 0.25,
        ease: "easeOut",
    }
);
```
می‌گویی حرکت چقدر طول بکشد و سرعت در طول آن چگونه تغییر کند. برای Fade، ورود و خروج پنل‌ها و بسیاری از انیمیشن‌های رابط کاربری مناسب است.

#### `spring`: حرکت با مدل فنر
```js
animate(
    card,
    { scale: 1.03 },
    {
        type: "spring",
        stiffness: 400,
        damping: 30,
    }
);
```

در این حالت، حرکت بر اساس پارامترهای فنر محاسبه می‌شود. `stiffness` سختی فنر و `damping` میزان کاهش نوسان را کنترل می‌کنند.
Motion از Spring فیزیکی و نیز Spring مبتنی بر مدت و Bounce پشتیبانی می‌کند.
قاعده عملی: برای ورود یک کارت، ابتدا `tween` را یاد بگیر. برای حرکاتی مثل تغییر اندازه یا پاسخ تعاملی، `spring` را آزمایش کن. قرار نیست همه انیمیشن‌ها فنری باشند.

## ۶. گزینه‌های تکرار و تأخیر

```js
animate(
    ".notification-indicator",
    {
        opacity: [0.4, 1],
    },
    {
        duration: 0.8,
        repeat: Infinity,
        repeatType: "reverse",
        repeatDelay: 0.2,
    }
);
```

معنی گزینه‌ها:

- `duration`: مدت یک اجرای انیمیشن
    
- `repeat`: تعداد تکرار؛ `Infinity` یعنی ادامه نامحدود
    
- `repeatType: "reverse"`: در هر تکرار جهت حرکت برعکس می‌شود
    
- `repeatDelay`: مکث میان تکرارها
    

این الگو برای یک نشانگر متحرک ساده مناسب است، اما انیمیشن دائمی را برای هر عنصر استفاده نکن؛ حرکت مداوم می‌تواند توجه کاربر را مختل کند. همچنین باید تنظیمات کاهش حرکت کاربر را در طراحی کامل‌تر در نظر بگیری.

## ۷. کنترل انیمیشن بعد از شروع

تا اینجا فقط انیمیشن اجرا کرده‌ایم. اما در برنامه واقعی، گاهی لازم است آن را متوقف کنیم، سرعت را تغییر بدهیم یا منتظر پایانش بمانیم.
`animate()` یک کنترل‌کننده انیمیشن برمی‌گرداند.

```js
const animation = animate(
    card,
    {
        opacity: [0, 1],
        y: [20, 0],
    },
    {
        duration: 0.5,
    }
);
```
حالا `animation` یک کنترل‌کننده است؛ می‌توانی با آن عملیات زیر را انجام بدهی:

```js
// توقف انیمیشن
animation.pause();

// ادامه
animation.play();

// تغییر سرعت پخش
animation.speed = 0.5;

// توقف کامل اجرا
animation.stop();
```

برای شروع، تفاوت `pause()` و `stop()` را به خاطر بسپار: مکث برای ادامه‌دادن در نظر گرفته شده است، اما توقف را نباید معادل مکث تلقی کرد.

### منتظر پایان انیمیشن بمان
```js
await animation;
```

در API فعلی Motion، کنترل‌کننده انیمیشن قابلیت انتظار با Promise را دارد. بنابراین می‌توانی ترتیب اجرای عملیات را مشخص کنی:

```js
async function showMessage(element) {
    const animation = animate(
        element,
        {
            opacity: [0, 1],
            y: [12, 0],
        },
        {
            duration: 0.3,
        }
    );

    await animation;

    console.log("انیمیشن تمام شد");
}
```
برای انیمیشن‌های یک‌باره، این روش مفید است؛ مثلاً وقتی می‌خواهی پس از پایان یک افکت، عملیات بعدی را انجام بدهی.

نکته: اگر انیمیشن را متوقف یا لغو کنی، نباید بدون بررسی وضعیت اجرا فرض کنی که همیشه به پایان طبیعی رسیده است. در معماری پیچیده‌تر باید مسیرهای لغو و خطا را هم مدیریت کنی.

### هر پوشه چه مسئولیتی دارد؟

- `core/`: تنظیمات مشترک و Presetهای انیمیشن که واقعاً بین چند ماژول استفاده می‌شوند.
    
- `ui/`: رفتارهای مستقل و قابل استفاده مجدد، مانند انیمیشن ورود کارت یا باز و بسته‌شدن Modal.
    
- `pages/`: هماهنگ‌کردن انیمیشن‌های مختص یک صفحه، مانند صفحه مدیریت قالب‌ها.
    
- `app.js`: اتصال ماژول‌ها به ورودی اصلی برنامه.
    

قاعده مهم: برای هر انیمیشن یک فایل نساز؛ برای هر رفتار یا مسئولیت مستقل، در صورت نیاز یک ماژول بساز. یک Fade ساده ممکن است فقط چند خط در ماژول همان کامپوننت باشد.
